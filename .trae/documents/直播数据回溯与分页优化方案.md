# 直播数据回溯与分页优化方案

## Context（为什么做）

当前数据全部落在 `data/live.db`（SQLite，WAL 模式）的三张表里，`events` 表已经逐条记录了每次弹幕、进场、关注、点赞、礼物、上舰、SC。但存在三个问题：

1. **实时弹幕流只能看"本次打开页面之后"新推来的消息**——SSE 只推增量，页面一刷新历史就没了，无法回看之前的弹幕。
2. **没有时间轴**：无法按日期/小时切换回看任意时间段的直播间实况。
3. **没有分页，后期会卡**：画像接口 [web.py](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/web.py#L106) 写死 `limit=200`，观众列表写死 `limit=300`，且都只能看到最近的，看不到全部。
4. 次要问题：`events` 表缺少 `session_id` 联合索引；「重连 / 更新 Cookie」也会新建场次，会把时间轴切碎。

**目标**：实时弹幕流可回看、按时间轴切换；观众画像能翻页查看全部行为；观众列表能翻页；上万条数据也不卡。

## 已确认的口径（来自用户）

- **离场**：B站协议不推送离场事件，**不做离场推断**，界面只展示「最后活跃」。
- **性能方案**：**页码分页**（不是无限滚动）。
- **「可保存」**：不需要导出文件，**数据库已持久化，界面能回溯即可**。
- **时间轴粒度**：**按小时 / 日期切换**。

## 不在本次范围

- 离场事件推断
- `storage.keep_days` 过期清理（该配置项目前完全没被读取，保持现状）
- 弹幕流导出为文件

## 后端改动

### 1. store.py

**新增索引**（加进 `SCHEMA`，`IF NOT EXISTS` 幂等）：

```sql
CREATE INDEX IF NOT EXISTS idx_events_session ON events(session_id, ts);
```

**`get_events()` 扩展过滤条件**（现有签名 [store.py#L229-L248](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/store.py#L229-L248)）：
新增可选参数 `session_id`、`from_ts`、`to_ts`，与现有 `uid` / `types` / `limit` / `offset` 组合，继续 `ORDER BY ts DESC, id DESC`。

**新增 `count_events_filtered()`**：与 `get_events` 同样的过滤条件，返回总数，供分页算总页数。保留现有 `count_events(uid)` 不动。

**新增 `list_sessions(limit=200)`**：

```sql
SELECT s.id, s.room_id, s.started_at, s.ended_at,
       (SELECT COUNT(*) FROM events e WHERE e.session_id = s.id) AS events,
       (SELECT COUNT(DISTINCT uid) FROM events e WHERE e.session_id = s.id) AS viewers
FROM sessions s ORDER BY s.started_at DESC LIMIT ?
```

**新增 `timeline_buckets()`**（按天 + 小时聚合，用本地时区）：

```sql
SELECT strftime('%Y-%m-%d', ts/1000, 'unixepoch', 'localtime') AS day,
       strftime('%H',        ts/1000, 'unixepoch', 'localtime') AS hour,
       COUNT(*) AS events, MIN(ts) AS first_ts, MAX(ts) AS last_ts
FROM events
GROUP BY day, hour
ORDER BY day DESC, hour DESC
```

返回按天分组的嵌套结构，供前端渲染两个下拉：`[{day, count, hours: [{hour, count, first_ts, last_ts}]}]`。

### 2. web.py

- **新增 `GET /api/timeline`** → `store.timeline_buckets()`，返回上面的嵌套结构。
- **新增 `GET /api/sessions`** → `store.list_sessions()`。
- **`GET /api/events` 扩展**（现 [web.py#L112-L116](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/web.py#L112-L116)）：支持 `session_id` / `uid` / `types`（逗号分隔）/ `from_ts` / `to_ts` / `limit`（默认 200，上限 500）/ `offset`，返回由 `{items}` 改为 `{items, total}`。
- **`GET /api/viewers/{uid}` 改成分页**（现 [web.py#L101-L110](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/web.py#L101-L110)）：支持 `limit`（默认 100）/ `offset` / `types` / `session_id`，返回 `{viewer, events, metrics, total}`。
  - **注意**：`metrics` 不能再用分页后的事件算（会失真）。改为单独查一份弹幕样本喂给 `analyzer.build_metrics()`（`store.get_events(uid=uid, limit=500, types=['danmaku'])`），与展示用的事件列表解耦。
- **`GET /api/viewers` 增加 `total`**（现 [web.py#L89-L99](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/web.py#L89-L99)），供观众列表分页。

### 3. main.py —— 修掉"重连切碎场次"

[restart_client()](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/main.py#L116-L120) 目前无条件 `end_session()` + `start_session()`，导致点「重连」、改 Cookie 都会新建场次。改为**只在房间号真的变了时才新建场次**，否则复用当前场次。新增实例属性 `self._session_room` 记录当前场次所属房间，`run()` 启动时一并赋值。

## 前端改动

### index.html

- 「实时弹幕流」面板头部新增：
  - 模式标识（`实时` / `回看中`）
  - 时间轴控件：`日期` 下拉 + `小时` 下拉（由 `/api/timeline` 填充）
  - `回到实时` 按钮（回看模式下才显示）
- 弹幕流底部、观众列表底部各加一个分页条容器。

### style.css

新增 `.timeline-bar`、`.mode-pill`、`.pager`（含按钮与"第 X / Y 页"）、`.pager:disabled` 等样式；历史模式下的弹幕行复用现有 `.line` 样式。

### app.js

**state 新增字段**：

```js
streamMode: 'live',      // 'live' | 'history'
timeline: null,          // /api/timeline 结果
historyDay: '', historyHour: '', historyPage: 1, historyTotal: 0,
behaviorPage: 1,
viewerPage: 1, viewerTotal: 0,
```

**弹幕流回看**：
- `loadTimeline()`：拉 `/api/timeline`，填充日期下拉；选中日期后填充小时下拉（显示 `14:00 (1,234)`）。
- `enterHistory(day, hour, page)`：用该小时的 `first_ts`/`last_ts` 作为 `from_ts`/`to_ts` 调 `/api/events`，`limit=200` + `offset`，**整体替换**弹幕流内容并显示分页条。
- `backToLive()`：切回 `live`，清空分页状态，恢复 SSE 追加。
- 渲染历史弹幕复用现有 [lineHtml()](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/static/app.js#L155-L171)，用 `DocumentFragment` 批量插入（每页 200 行，避免大字符串 + 多次 reflow）。
- SSE 回调里 `data.type === 'event'` 时**只有 `streamMode === 'live'` 才追加到弹幕流**；回看模式下仍照常更新观众列表/角标。

**画像「行为」分类分页**：`switchProfileTab` 与 `tabBehaviorHtml` 改为渲染分页条（每页 100 条 + 上一页/下一页/页码）；翻页只调 `loadBehaviorPage(uid, page)`，仅刷新 `#behavior-list` 与分页条，不重建整个画像面板（避免丢失滚动位置与闪烁）。

**观众列表分页**：`loadViewers()` 带 `offset`，底部渲染分页条；筛选/排序/搜索时重置到第 1 页。

**性能要点**：
- 任何列表每页最多渲染 100~200 行 DOM，杜绝一次性渲染上千行。
- 历史弹幕用 `DocumentFragment` 批量插入。
- 翻页只局部更新，不做整面板 `innerHTML` 重写。
