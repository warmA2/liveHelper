# 直播数据可视化（密度曲线）方案

## Context

当前助手已经能落库并展示「观众 / 事件 / 弹幕流」，但数据都是以**列表和数字**呈现，看不出「节奏」。
主播实际关心的是：**什么时候弹幕炸了、什么时候进人多、谁在什么时候开始送礼**。

本次要补上「数据 → 图形」这一层，做两个曲线图：

1. **全局实时密度曲线**：固定在「弹幕流」面板顶部，随时间滚动展示弹幕密度 / 入场密度 / 礼物密度，一眼看出直播节奏。
2. **观众个人行为曲线**：放在右侧画像面板的**概览页**，展示单个观众的活跃时段分布与时间趋势，回答「什么时候说话 / 进场 / 送礼、发言与付费频次如何」。

技术选型（已与用户确认）：图表用 **ECharts（CDN 加载）**；个人曲线放**概览页**。

## 一、后端：新增时间分桶聚合

### 1. `store.py` —— 新增 `event_density()`

复用现有 [`_event_filters`](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/store.py#L245-L271)（已支持 `uid / session_id / types / from_ts / to_ts`），按下取整的时间桶聚合：

```python
def event_density(self, uid=None, session_id=None, types=None,
                  from_ts=None, to_ts=None, bucket_ms=60000) -> dict:
    bucket_ms = max(int(bucket_ms), 1000)
    where, params = self._event_filters(uid, session_id, types, from_ts, to_ts)
    with self._lock:
        rows = self.conn.execute(
            f"SELECT (ts / ?) * ? AS bucket, type, COUNT(*) AS n "
            f"FROM events WHERE {where} GROUP BY bucket, type ORDER BY bucket",
            [bucket_ms, bucket_ms, *params],
        ).fetchall()
    # 组装 {groups: {type: [[ts, n], ...]}, totals: {type: n}, total}
```

要点：`ts` 是毫秒且为 INTEGER，SQLite 整数除法 `ts / ?` 即为分桶下取整，无需额外函数。
返回结构统一为：

```json
{ "bucket_ms": 60000, "from_ts": 0, "to_ts": 0,
  "groups": { "danmaku": [[1730000000000, 12], ...] },
  "totals": { "danmaku": 340 }, "total": 512 }
```

### 2. `web.py` —— 新增路由 `/api/density`

在 [`build_app`](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/web.py#L53-L74) 的路由表里加 `web.get("/api/density", self.api_density)`，handler 复用现有 `_query_int` / `_query_types` 辅助方法：

```python
async def api_density(self, request):
    q = request.query
    bucket = min(max(self._query_int(q, "bucket", 60), 5), 86400)  # 秒
    return web.json_response(self.store.event_density(
        uid=self._query_int(q, "uid", 0) or None,
        session_id=self._query_int(q, "session_id", 0) or None,
        types=self._query_types(q),
        from_ts=self._query_int(q, "from_ts", 0) or None,
        to_ts=self._query_int(q, "to_ts", 0) or None,
        bucket_ms=bucket * 1000,
    ))
```

**不改动任何现有接口**，纯增量。

失败时在 `#density-chart` 里显示提示文案，不影响其它功能。

**b. 全局密度曲线**

- `state` 增加 `densityMetric:'danmaku'`、`densityChart:null`、`densityTimer:null`。
- 指标 → 事件类型映射：
  - `danmaku` → `['danmaku']`
  - `enter` → `['enter']`
  - `gift` → `['gift','superchat','guard']`
  - `all` → 不传 `types`，按 `danmaku / enter / gift+superchat+guard / 其它` 拆成多条堆叠面积。
- `loadDensity()`：确定时间窗后请求 `/api/density`：
  - **实时模式**：`to_ts = Date.now()`，`from_ts = to_ts - 30min`，`bucket = 60`。
  - **回看模式**：用所选 `#tl-day/#tl-hour` 对应 slot 的 `first_ts ~ last_ts`，`bucket = 60`。
  - 用 ECharts 折线+面积渲染，`xAxis` 为 `time` 类型，标题区展示窗口内总量 / 峰值。
- `mountDensityChart()` 初始化实例；`setDensityMetric()` 切指标后立即重载。
- `init()` 里 `ensureECharts().then(mountDensityChart).then(loadDensity)`，并 `setInterval(loadDensity, 5000)` 做 5 秒滚动刷新。
- 在 [`setStreamMode`](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/static/app.js#L318-L328) / [`enterHistory`](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/static/app.js#L330-L356) / `backToLive` 末尾调用 `loadDensity()`，让曲线跟随时间轴切换。

**c. 观众个人曲线（概览页）**

在 [`tabOverviewHtml`](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/static/app.js#L486-L517) 末尾追加一个 section：

- 频次 chips：发言次数、进场次数、付费次数、礼物金额、活跃天数、日均条数（多数可直接用 `viewer.*` / `metrics.*`）。
- 两张图容器：`#user-hour-chart`（**活跃时段分布**，0–23 点堆叠柱：弹幕/进场/礼物）、`#user-trend-chart`（**时间趋势**，折线面积）。

数据加载 `mountUserCharts(viewer)`（在 [`renderProfile`](file:///C:/Users/25988/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac0000df6130bae3268a8ac/static/app.js#L700-L717) 里 `tab === 'overview'` 时调用）：

- 用 `viewer.first_seen / last_seen`（毫秒）作为跨度。
- **活跃时段分布**：请求 `/api/density?uid=&from_ts=&to_ts=` + `bucket=3600`，前端把桶时间戳按**本地小时** 0–23 归并成堆叠柱。
- **时间趋势**：自适应桶（`bucket = clamp(round(span/200/1000), 300, 86400)`）再请求一次，折线面积展示事件密度随时间变化。
- 每次渲染前 `dispose()` 旧实例，避免 ECharts 实例泄漏。

**d. 自适应尺寸**

用 `ResizeObserver` 监听两个图表容器（以及窗口 resize），触发 `chart.resize()`——这样拖动 `#splitter` 改变画像栏宽度时曲线会自动重排。

### 4. 复用与约束

- 完全复用现有 `_event_filters`、`_query_int`、`_query_types`、`fmtTime/fmtFull/esc` 等，不重复造轮子。
- 不新增 Python 依赖，不改数据库结构。
- ECharts 是唯一新增外部依赖（CDN）。若线上 CDN 在用户网络下不可达，可改为把 `echarts.min.js` 下载到 `static/vendor/` 本地引用作为兜底方案。

## 三、验证

1. **接口自检**：重启服务后，用 PowerShell 调
   `/api/density?bucket=60`、`?uid=<某观众>&bucket=3600`、`?types=danmaku&bucket=300`，确认返回 `groups/totals/bucket_ms` 结构正确、桶时间戳落在合理区间。
2. **前端端到端（browser_use 子代理）**：打开 `http://127.0.0.1:8765/`
   - 弹幕流顶部出现密度曲线，切换「弹幕/进场/礼物/全部」四个指标图会变化；
   - 用时间轴切到某个历史小时，曲线切到该小时窗口；点「回到实时」恢复正常；
   - 点击任一观众 → 概览页出现「活跃时段分布」与「时间趋势」两张图及频次 chips；
   - 拖动分隔条改变画像栏宽度，图表随宽度自适应；控制台无 JS 报错。
3. **回归**：确认弹幕流、观众列表分页、时间轴回看、行为分页、画像各标签均正常（本次为增量改动）。
